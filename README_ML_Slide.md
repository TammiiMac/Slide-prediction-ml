# Прогнозирование слайда в метрах при наклонно-направленном бурении

## Задача
Предсказать, сколько метров слайда потребуется на следующей свечке, 
чтобы попасть в целевую траекторию. 
Практическая инженерная задача в бурении с использованием ВЗД(винтового забойного двигателя)

## Зачем
Я работаю полевым инженером в бурении. Каждый день вижу, как инженер DD 
«на глаз» решает, сколько слайда дать — и ошибается. Захотел проверить: 
можно ли это предсказать **по данным**? Это не учебная задача — это **моя работа**.

## Данные
- **551 замер** из отчётов Weatherford (анонимизированы), Perfomance files с Slide sheet для бурения(запись параметров бурения RealTime).

- **Признаки (X):** глубина, зенитный угол, азимут, ROP, RPM, WOB, Flow, 
   Лаговые признаки (prev_inc, prev_azi, prev_slide, prev_dls, prev_rop), 
   delta_inc (изменение угла).
- **Цель (y):** `slide_fact` — фактические метры слайда.

## Подход
1. **Очистка:** 1. Удалены пустые строки, NaN заполнены медианой, 
                2. аномалии `slide_fact > 25 м` отфильтрованы.
2. **Feature engineering:** 1. лаговые признаки (что было до свечки), 
                            2. delta_inc (эффективность прошлого слайда).
3. **Хронологический split** (80/20) — без утечки из будущего.
4. **Модели:** LinearRegression, RandomForest, GradientBoosting.

## Что меня удивило
- `rop` оказался важнее `delta_inc` (56% vs 1.5%). Думал, что «изменение угла» 
  главное — а модель нашла **нелинейные** связи через скорость проходки.
- Модель **ошибается на 5 м** — это **много** для инженера (слайд 6 м ± 5 м = 
  от 1 до 11). Но **лучше** «на глаз» (baseline 6.76).
- **Утечка** `dls` — я **сам** чуть не пропустил (корреляция 0.81). Понял, 
  что DLS **вычисляется после** слайда — а значит, «подсматривает» ответ.

## Результаты
| Модель | MAE (м) | R² |
|---|---|---|
| Baseline (среднее) | 6.76 | — |
| LinearRegression | 7.05 | — |
| RandomForest | 5.07 | 0.07 |
| **GradientBoosting** | **4.96** | **0.18** |

- **Улучшение MAE: 27%** относительно baseline.
- **Главный признак:** `rop` (56% важности) — скорость проходки.
- **Устранена утечка:** `dls` (текущий) исключён — вычисляется после слайда.

## Проверка
1. **Сначала baseline** (среднее) — 6.76 м. **Без** него не понятно, 
   «хороша» ли модель.
2. **Проверил утечку**: `dls` коррелировал с целью на **0.81** — убрал.
3. **Сравнил 3 модели** — линейная **не работает** (7.05, хуже baseline), 
   RF 5.07, GB **4.96** (лучшая).
4. **Посмотрел важность** — `rop` 56%, `depth` 17% — **физически** логично.

## Выводы
- Модель **честно** предсказывает метры слайда, ошибаясь в среднем на **5 м**.
- `rop` — ключевой предиктор (физика: твёрдость породы).
- R² 0.18 — для инженерных данных ожидаемо (много неучтённых факторов: 
  геология, износ долота, опыт инженера).

  ## Ограничения
- **551 замер** — **мало**. Модель может **переобучиться** на конкретную скважину.
- **R² 0.18** — модель объясняет **только 18%** дисперсии. Остальное — 
  геология, износ долота, опыт инженера (не в данных).
- **`slide_ratio` и `delta_azi`** создал, но **не использовал** — не успел 
  проверить, улучшат ли.
- **Данные анонимизированы** — реальные названия скважин убрал.
